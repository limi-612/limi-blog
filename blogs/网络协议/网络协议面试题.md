## HTTP协议基础

### 1. HTTP 是什么？有什么特点？

- **定义**：超文本传输协议（HyperText Transfer Protocol），应用层协议
- **特点**：
  - **无状态**：每次请求独立，服务器不保存客户端状态
  - **无连接**：每次请求建立连接，响应后断开（HTTP/1.0）
  - **请求-响应模式**：客户端发起请求，服务器返回响应
  - **灵活**：可传输任意类型数据
  - **明文传输**：HTTP 不加密（HTTPS 加密）

### 2. HTTP 请求和响应的组成？

- **请求组成**：
  - **请求行**：方法、URL、协议版本
  - **请求头**：Host、User-Agent、Content-Type 等
  - **空行**：分隔头部和主体
  - **请求体**：POST/PUT 等方法的参数

```http
GET /api/users HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Content-Type: application/json

{"name": "John"}
```

- **响应组成**：
  - **状态行**：协议版本、状态码、状态描述
  - **响应头**：Content-Type、Content-Length 等
  - **空行**：分隔头部和主体
  - **响应体**：实际数据

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 123

{"data": "response"}
```

### 3. HTTP 状态码详解

- **1xx 信息响应**：
  - `100 Continue`：客户端应继续请求
  - `101 Switching Protocols`：协议切换

- **2xx 成功响应**：
  - `200 OK`：请求成功
  - `201 Created`：资源创建成功
  - `204 No Content`：无内容返回
  - `206 Partial Content`：部分内容（断点续传）

- **3xx 重定向**：
  - `301 Moved Permanently`：永久重定向，浏览器会缓存
  - `302 Found`：临时重定向，浏览器不缓存
  - `304 Not Modified`：资源未修改，使用缓存
  - `307 Temporary Redirect`：临时重定向，保持方法不变

- **4xx 客户端错误**：
  - `400 Bad Request`：请求语法错误
  - `401 Unauthorized`：需要认证
  - `403 Forbidden`：禁止访问
  - `404 Not Found`：资源不存在
  - `405 Method Not Allowed`：方法不允许

- **5xx 服务器错误**：
  - `500 Internal Server Error`：服务器内部错误
  - `502 Bad Gateway`：网关错误
  - `503 Service Unavailable`：服务不可用
  - `504 Gateway Timeout`：网关超时

### 4. HTTP 方法详解

- **GET**：
  - 获取资源
  - 幂等性：多次请求结果相同
  - 可缓存
  - 参数在 URL 中

- **POST**：
  - 创建资源
  - 非幂等
  - 不可缓存
  - 参数在请求体中

- **PUT**：
  - 更新资源（完整替换）
  - 幂等性
  - 不可缓存

- **PATCH**：
  - 部分更新资源
  - 非幂等
  - 不可缓存

- **DELETE**：
  - 删除资源
  - 幂等性
  - 不可缓存

- **HEAD**：
  - 获取响应头，不返回响应体
  - 用于检查资源是否存在

- **OPTIONS**：
  - 获取服务器支持的 HTTP 方法
  - 用于 CORS 预检请求

### 5. GET 和 POST 的区别？

- **参数位置**：
  - GET：参数在 URL 中（query string）
  - POST：参数在请求体中

- **参数长度**：
  - GET：受 URL 长度限制（通常 2048 字符）
  - POST：理论上无限制

- **安全性**：
  - GET：参数暴露在 URL，不安全
  - POST：参数在请求体，相对安全

- **缓存**：
  - GET：可被缓存
  - POST：不可缓存

- **幂等性**：
  - GET：幂等
  - POST：非幂等

- **使用场景**：
  - GET：查询数据
  - POST：提交数据、创建资源

## HTTPS与安全

### 1. HTTPS 是什么？和 HTTP 的区别？

- **定义**：HTTP + SSL/TLS，加密的 HTTP 协议
- **区别**：
  - **端口**：HTTP 80，HTTPS 443
  - **加密**：HTTPS 加密传输，HTTP 明文传输
  - **证书**：HTTPS 需要 CA 证书
  - **性能**：HTTPS 有加密开销，稍慢
  - **SEO**：HTTPS 对 SEO 更友好

### 2. TLS/SSL 握手过程详解

- **完整握手流程**：
  1. **Client Hello**：
     - 客户端发送支持的 TLS 版本
     - 支持的加密套件列表
     - 随机数（Client Random）
     - 支持的压缩方法

  2. **Server Hello**：
     - 服务器选择 TLS 版本和加密套件
     - 发送服务器证书
     - 随机数（Server Random）

  3. **证书验证**：
     - 客户端验证证书有效性
     - 检查证书链
     - 验证域名匹配

  4. **密钥交换**：
     - 客户端生成预主密钥（Pre-Master Secret）
     - 使用服务器公钥加密后发送
     - 双方计算主密钥（Master Secret）

  5. **Finished**：
     - 双方发送加密的 Finished 消息
     - 验证握手完整性
     - 开始加密通信

- **握手优化**：
  - **会话复用**：使用 Session ID 或 Session Ticket
  - **TLS 1.3**：减少握手往返次数

### 3. 证书验证过程

- **验证步骤**：
  1. **证书有效期**：检查证书是否过期
  2. **域名匹配**：检查证书域名是否匹配
  3. **证书链验证**：验证证书链完整性
  4. **CA 信任**：检查 CA 是否在信任列表中
  5. **证书撤销**：检查证书是否被撤销（CRL/OCSP）

```javascript
// 证书验证要点
const verifyCertificate = (cert, hostname) => {
    // 1. 检查有效期
    const now = Date.now();
    if (now < cert.validFrom || now > cert.validTo) {
        throw new Error('Certificate expired');
    }
    
    // 2. 检查域名
    if (!cert.subjectAltName.includes(hostname)) {
        throw new Error('Hostname mismatch');
    }
    
    // 3. 验证证书链
    if (!verifyChain(cert)) {
        throw new Error('Invalid certificate chain');
    }
    
    // 4. 检查 CA 信任
    if (!isTrustedCA(cert.issuer)) {
        throw new Error('Untrusted CA');
    }
};
```

### 4. 常见的网络安全问题？

- **XSS（跨站脚本攻击）**：
  - **存储型**：恶意脚本存储在服务器
  - **反射型**：恶意脚本在 URL 参数中
  - **DOM 型**：客户端脚本修改 DOM
  - **防护**：输入验证、输出转义、CSP

- **CSRF（跨站请求伪造）**：
  - 利用用户已登录状态发起请求
  - **防护**：Token、SameSite Cookie、验证 Referer

- **SQL 注入**：
  - 恶意 SQL 代码注入
  - **防护**：参数化查询、输入验证

- **中间人攻击**：
  - 拦截通信
  - **防护**：HTTPS、证书固定

### 5. 如何防止 XSS 攻击？

- **输入验证**：
  - 过滤危险字符
  - 白名单验证

- **输出转义**：
  - HTML 转义：`<` → `&lt;`
  - JavaScript 转义
  - URL 编码

- **CSP（内容安全策略）**：
```html
<meta http-equiv="Content-Security-Policy" 
      content="default-src 'self'; script-src 'self' 'unsafe-inline';">
```

- **HttpOnly Cookie**：
  - 防止 JavaScript 访问 Cookie
  - 减少 XSS 影响

### 6. 如何防止 CSRF 攻击？

- **Token 验证**：
  - 服务器生成随机 Token
  - 表单提交时验证 Token

- **SameSite Cookie**：
```javascript
Set-Cookie: session=xxx; SameSite=Strict
```

- **验证 Referer**：
  - 检查请求来源
  - 只接受同源请求

- **双重 Cookie**：
  - 设置两个 Cookie
  - 一个 HttpOnly，一个可访问
  - 提交时验证两个 Cookie

## HTTP缓存机制

### 1. 为什么需要缓存？

- **减少网络请求**：降低服务器压力
- **提升响应速度**：本地读取更快
- **节省带宽**：减少数据传输
- **改善用户体验**：页面加载更快

### 2. 强缓存（强缓存）

- **定义**：浏览器直接使用缓存，不向服务器请求
- **响应头**：
  - `Cache-Control`：优先级高，HTTP/1.1
    - `max-age=3600`：缓存 3600 秒
    - `no-cache`：需要验证
    - `no-store`：不缓存
    - `private`：仅客户端缓存
    - `public`：可被代理缓存
  - `Expires`：过期时间，HTTP/1.0，优先级低

```javascript
// 服务器设置
res.setHeader('Cache-Control', 'max-age=3600, public');
res.setHeader('Expires', new Date(Date.now() + 3600000).toUTCString());

// 浏览器判断流程
// 1. 检查 Cache-Control max-age
// 2. 检查 Expires
// 3. 如果未过期，直接使用缓存（200 from cache）
// 4. 如果过期，发起请求验证
```

### 3. 协商缓存（对比缓存）

- **定义**：需要向服务器验证资源是否更新
- **ETag**：
  - 服务器生成资源唯一标识
  - 客户端发送 `If-None-Match`
  - 匹配返回 304，不匹配返回 200

```javascript
// ETag 实现
app.get('/api/data', (req, res) => {
    const data = getData();
    const etag = generateETag(data); // 如：W/"abc123"
    
    if (req.headers['if-none-match'] === etag) {
        return res.status(304).end(); // Not Modified
    }
    
    res.setHeader('ETag', etag);
    res.json(data);
});
```

- **Last-Modified**：
  - 服务器返回最后修改时间
  - 客户端发送 `If-Modified-Since`
  - 匹配返回 304，不匹配返回 200

```javascript
// Last-Modified 实现
app.get('/api/file', (req, res) => {
    const stats = fs.statSync(filePath);
    const lastModified = stats.mtime.toUTCString();
    
    if (req.headers['if-modified-since'] === lastModified) {
        return res.status(304).end();
    }
    
    res.setHeader('Last-Modified', lastModified);
    res.sendFile(filePath);
});
```

- **ETag vs Last-Modified**：
  - ETag 更精确（内容变化检测）
  - Last-Modified 只能精确到秒
  - 两者可同时使用，ETag 优先级更高

### 4. 缓存策略

- **HTML 文件**：
  - `Cache-Control: no-cache`
  - 需要验证，确保获取最新版本

- **静态资源（JS/CSS/图片）**：
  - `Cache-Control: max-age=31536000, immutable`
  - 长期缓存，文件名带 hash

- **API 响应**：
  - `Cache-Control: no-cache` 或 `max-age=0`
  - 需要验证，使用 ETag

### 5. 缓存流程总结

```
1. 浏览器发起请求
2. 检查强缓存（Cache-Control/Expires）
   ├─ 未过期 → 返回缓存（200 from cache）
   └─ 已过期 → 继续步骤 3
3. 向服务器发起请求，携带验证头
   ├─ If-None-Match (ETag)
   └─ If-Modified-Since (Last-Modified)
4. 服务器验证
   ├─ 未修改 → 返回 304 Not Modified
   └─ 已修改 → 返回 200 + 新资源
```

## 跨域问题

### 1. 什么是跨域？为什么会有跨域？

- **定义**：浏览器同源策略限制，不同源之间的请求被阻止
- **同源条件**：
  - 协议相同（http/https）
  - 域名相同
  - 端口相同
- **跨域场景**：
  - 不同域名：`http://a.com` → `http://b.com`
  - 不同端口：`http://localhost:3000` → `http://localhost:8080`
  - 不同协议：`http://example.com` → `https://example.com`

### 2. 跨域解决方案

- **CORS（跨域资源共享）**：
  - 服务器设置响应头允许跨域
  - 简单请求：GET、POST、HEAD
  - 预检请求：PUT、DELETE 等需要 OPTIONS 预检

```javascript
// 服务器设置 CORS
app.use((req, res, next) => {
    res.setHeader('Access-Control-Allow-Origin', '*'); // 或指定域名
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization');
    res.setHeader('Access-Control-Allow-Credentials', 'true'); // 允许携带 Cookie
    next();
});
```

- **JSONP**：
  - 利用 `<script>` 标签不受同源限制
  - 只能 GET 请求
  - 需要服务器支持

```javascript
// 客户端
function jsonp(url, callback) {
    const script = document.createElement('script');
    script.src = `${url}?callback=${callback}`;
    document.body.appendChild(script);
}

// 服务器
app.get('/api/data', (req, res) => {
    const callback = req.query.callback;
    const data = { message: 'Hello' };
    res.send(`${callback}(${JSON.stringify(data)})`);
});
```

- **代理服务器**：
  - 前端请求同源代理
  - 代理转发到目标服务器

```javascript
// 开发环境代理（webpack/vite）
module.exports = {
    devServer: {
        proxy: {
            '/api': {
                target: 'http://localhost:8080',
                changeOrigin: true
            }
        }
    }
};
```

- **postMessage**：
  - 用于 iframe 通信
  - 跨窗口消息传递

```javascript
// 父窗口
window.postMessage('Hello', 'http://child.com');

// 子窗口
window.addEventListener('message', (event) => {
    if (event.origin === 'http://parent.com') {
        console.log(event.data);
    }
});
```

### 3. CORS 预检请求（Preflight）

- **触发条件**：
  - 非简单请求方法（PUT、DELETE 等）
  - 自定义请求头
  - Content-Type 为 `application/json`

- **预检流程**：
  1. 浏览器发送 OPTIONS 预检请求
  2. 服务器返回允许的请求方法和头
  3. 浏览器检查是否允许
  4. 允许则发送实际请求

```javascript
// 预检请求示例
// 1. 浏览器发送 OPTIONS
OPTIONS /api/users HTTP/1.1
Origin: http://localhost:3000
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Content-Type

// 2. 服务器响应
HTTP/1.1 200 OK
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: PUT, POST, GET
Access-Control-Allow-Headers: Content-Type

// 3. 浏览器发送实际请求
PUT /api/users HTTP/1.1
Origin: http://localhost:3000
Content-Type: application/json
```

## WebSocket协议

### 1. WebSocket 是什么？和 HTTP 的区别？

- **定义**：全双工通信协议，建立在 TCP 之上
- **特点**：
  - 持久连接
  - 双向通信
  - 低延迟
  - 服务器可主动推送

- **与 HTTP 区别**：
  - HTTP：请求-响应，单向
  - WebSocket：双向通信，持久连接
  - HTTP：无状态
  - WebSocket：有状态

### 2. WebSocket 连接建立

- **握手过程**：
  1. 客户端发送 HTTP Upgrade 请求
  2. 服务器响应 101 Switching Protocols
  3. 连接升级为 WebSocket

```javascript
// 客户端
const ws = new WebSocket('ws://localhost:8080');

ws.onopen = () => {
    console.log('连接已建立');
    ws.send('Hello Server');
};

ws.onmessage = (event) => {
    console.log('收到消息:', event.data);
};

ws.onerror = (error) => {
    console.error('错误:', error);
};

ws.onclose = () => {
    console.log('连接已关闭');
};

// 服务端 (Node.js)
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws, req) => {
    console.log('新连接');
    
    ws.on('message', (message) => {
        console.log('收到:', message);
        ws.send(`Echo: ${message}`);
    });
    
    ws.on('close', () => {
        console.log('连接关闭');
    });
});
```

### 3. WebSocket 心跳机制

- **目的**：
  - 检测连接是否存活
  - 防止连接被中间设备关闭
  - 自动重连

```javascript
class WebSocketClient {
    constructor(url) {
        this.url = url;
        this.heartbeatInterval = 30000; // 30秒
        this.reconnectDelay = 5000; // 5秒
        this.maxReconnectAttempts = 5;
        this.reconnectAttempts = 0;
        this.connect();
    }
    
    connect() {
        this.ws = new WebSocket(this.url);
        
        this.ws.onopen = () => {
            console.log('连接成功');
            this.reconnectAttempts = 0;
            this.startHeartbeat();
        };
        
        this.ws.onmessage = (event) => {
            const data = JSON.parse(event.data);
            if (data.type === 'pong') {
                this.lastPong = Date.now();
            } else {
                this.handleMessage(data);
            }
        };
        
        this.ws.onclose = () => {
            console.log('连接关闭');
            this.stopHeartbeat();
            this.reconnect();
        };
        
        this.ws.onerror = (error) => {
            console.error('连接错误:', error);
        };
    }
    
    startHeartbeat() {
        this.heartbeatTimer = setInterval(() => {
            if (this.ws.readyState === WebSocket.OPEN) {
                this.ws.send(JSON.stringify({ type: 'ping' }));
                
                // 检查是否收到 pong
                setTimeout(() => {
                    if (Date.now() - this.lastPong > this.heartbeatInterval * 2) {
                        this.ws.close();
                    }
                }, 1000);
            }
        }, this.heartbeatInterval);
    }
    
    stopHeartbeat() {
        if (this.heartbeatTimer) {
            clearInterval(this.heartbeatTimer);
        }
    }
    
    reconnect() {
        if (this.reconnectAttempts < this.maxReconnectAttempts) {
            this.reconnectAttempts++;
            setTimeout(() => {
                console.log(`重连尝试 ${this.reconnectAttempts}`);
                this.connect();
            }, this.reconnectDelay);
        }
    }
    
    handleMessage(data) {
        // 处理业务消息
        console.log('收到消息:', data);
    }
}
```

## TCP/IP协议栈

### 1. OSI 七层模型和 TCP/IP 四层模型

- **OSI 七层模型**：
  1. 物理层：传输比特流
  2. 数据链路层：帧传输
  3. 网络层：IP 路由
  4. 传输层：TCP/UDP
  5. 会话层：建立会话
  6. 表示层：数据格式转换
  7. 应用层：HTTP/FTP/SMTP

- **TCP/IP 四层模型**：
  1. 网络接口层：物理+数据链路
  2. 网络层：IP、ICMP
  3. 传输层：TCP、UDP
  4. 应用层：HTTP、FTP、DNS

### 2. TCP 和 UDP 的区别？

- **TCP（传输控制协议）**：
  - **可靠**：保证数据顺序和完整性
  - **连接**：需要建立连接（三次握手）
  - **面向字节流**：数据流传输
  - **流量控制**：滑动窗口
  - **拥塞控制**：慢启动、拥塞避免
  - **开销大**：头部 20 字节
  - **应用**：HTTP、FTP、SMTP

- **UDP（用户数据报协议）**：
  - **不可靠**：不保证数据到达
  - **无连接**：不需要建立连接
  - **面向报文**：数据报传输
  - **无流量控制**：发送速度不受限制
  - **开销小**：头部 8 字节
  - **应用**：DNS、视频直播、游戏

### 3. TCP 三次握手详解

- **目的**：确认双方收发能力，建立可靠连接
- **过程**：
  1. **客户端 → 服务器（SYN）**：
     - 发送 SYN=1，seq=x
     - 客户端进入 SYN_SENT 状态

  2. **服务器 → 客户端（SYN-ACK）**：
     - 发送 SYN=1，ACK=1，seq=y，ack=x+1
     - 服务器进入 SYN_RCVD 状态

  3. **客户端 → 服务器（ACK）**：
     - 发送 ACK=1，seq=x+1，ack=y+1
     - 双方进入 ESTABLISHED 状态

- **为什么是三次？**：
  - 两次无法确认客户端接收能力
  - 防止已失效的连接请求到达服务器

### 4. TCP 四次挥手详解

- **目的**：安全关闭连接，确保数据完整传输
- **过程**：
  1. **客户端 → 服务器（FIN）**：
     - 发送 FIN=1，seq=u
     - 客户端进入 FIN_WAIT_1 状态

  2. **服务器 → 客户端（ACK）**：
     - 发送 ACK=1，ack=u+1
     - 服务器进入 CLOSE_WAIT 状态
     - 客户端进入 FIN_WAIT_2 状态

  3. **服务器 → 客户端（FIN）**：
     - 发送 FIN=1，seq=w
     - 服务器进入 LAST_ACK 状态

  4. **客户端 → 服务器（ACK）**：
     - 发送 ACK=1，ack=w+1
     - 客户端进入 TIME_WAIT 状态
     - 等待 2MSL 后关闭

- **为什么是四次？**：
  - TCP 全双工，需要双方都关闭
  - 服务器可能还有数据要发送

- **TIME_WAIT 的作用**：
  - 确保最后一个 ACK 到达
  - 防止旧连接的数据包影响新连接
  - 通常等待 2MSL（Maximum Segment Lifetime）

### 5. TCP 的流量控制

- **滑动窗口**：
  - 接收方告知发送方可接收的数据量
  - 动态调整窗口大小
  - 防止发送方发送过快

- **工作原理**：
  - 接收方在 ACK 中携带窗口大小
  - 发送方根据窗口大小调整发送速率
  - 窗口为 0 时停止发送

### 6. TCP 的拥塞控制

- **慢启动**：
  - 初始拥塞窗口 cwnd = 1
  - 每收到 ACK，cwnd 指数增长
  - 达到慢启动阈值 ssthresh 后进入拥塞避免

- **拥塞避免**：
  - cwnd 线性增长
  - 每 RTT 增加 1

- **快重传**：
  - 收到 3 个重复 ACK 立即重传
  - 不等待超时

- **快恢复**：
  - 重传后进入拥塞避免
  - 不回到慢启动

### 1. 内容分发
```javascript
// CDN节点选择算法
const selectCDNNode = (userIP, availableNodes) => {
    return availableNodes
        .map(node => ({
            node,
            distance: calculateDistance(userIP, node.ip),
            load: node.currentLoad
        }))
        .sort((a, b) => {
            // 综合考虑距离和负载
            return (a.distance * 0.7 + a.load * 0.3) - 
                   (b.distance * 0.7 + b.load * 0.3);
        })[0].node;
};
```

## HTTP/2 和 HTTP/3

### 1. HTTP/2 的特性？

- **多路复用**：
  - 单个连接处理多个请求
  - 解决 HTTP/1.1 队头阻塞
  - 请求和响应并行

- **头部压缩**：
  - 使用 HPACK 算法
  - 减少头部大小
  - 维护头部表

- **服务器推送**：
  - 服务器主动推送资源
  - 减少往返次数

- **二进制分帧**：
  - 数据以二进制帧传输
  - 更高效解析

### 2. HTTP/3 的特性？

- **基于 UDP**：
  - 使用 QUIC 协议
  - 解决 TCP 队头阻塞

- **0-RTT 连接**：
  - 首次连接更快
  - 会话复用

- **连接迁移**：
  - IP 变化保持连接
  - 适合移动网络

## 其他网络知识点

### 1. 从输入 URL 到页面显示的过程？

1. **DNS 解析**：域名 → IP 地址
2. **TCP 连接**：三次握手建立连接
3. **发送 HTTP 请求**：请求头和请求体
4. **服务器处理**：处理请求，返回响应
5. **接收响应**：接收 HTTP 响应
6. **解析 HTML**：构建 DOM 树
7. **解析 CSS**：构建 CSSOM 树
8. **渲染树**：DOM + CSSOM
9. **布局**：计算元素位置
10. **绘制**：渲染到屏幕

### 2. 常见的 HTTP 请求头？

- **通用头**：
  - `Cache-Control`：缓存控制
  - `Connection`：连接方式
  - `Date`：日期时间

- **请求头**：
  - `Accept`：接受的内容类型
  - `Accept-Encoding`：接受的编码
  - `Authorization`：认证信息
  - `Cookie`：Cookie 信息
  - `User-Agent`：用户代理
  - `Referer`：来源页面

- **响应头**：
  - `Content-Type`：内容类型
  - `Content-Length`：内容长度
  - `Set-Cookie`：设置 Cookie
  - `Location`：重定向地址
  - `Server`：服务器信息

### 3. Cookie、Session、Token 的区别？

- **Cookie**：
  - 存储在客户端
  - 每次请求自动携带
  - 大小限制 4KB
  - 可设置过期时间

- **Session**：
  - 存储在服务器
  - 通过 SessionID 标识
  - 更安全
  - 占用服务器内存

- **Token（JWT）**：
  - 无状态
  - 包含用户信息
  - 可跨域
  - 需要手动携带
