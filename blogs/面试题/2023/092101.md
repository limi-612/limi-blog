## 一、核心概念
1. Rreact的理解
- react是一个用于构造用户界面的javascript库，主要用户构建单页面应用中的视图层，采用组件化开发模式，使得构建和维护大型应用更加容易。
- 核心概念：组件，react基本单位是组件，可以是函数组件和类组件，接收输入props，返回元素，组件可以嵌套和组合。虚拟DOM，react使用虚拟DOM来提高性能，是真实DOM的抽象，当组件状态发生变化，react会重新渲染组件生成新的虚拟DOM树，然后通过diff算法比较新旧虚拟DOM树，计算出需要更新的最小变化，然后批量更新到真实DOM上。
- 状态（state）与属性(props)：state，组件内部的状态，可以通过setState（类组件）或者useState钩子函数（函数组件）来更新。状态更新会触发组件的渲染。props，从父组件传递给子组件的数据，是只读的，props的改变也会引起组件的重新渲染。
- 生命周期和钩子：生命周期，类组件有挂载、更新和卸载等生命周期方法，如componentDidMount、componentDidUpdate、componentWillUnmount等。Hook，函数组件中和可以使用Hooks来管理组件状态和副作用，例如useState、useEffect、useContext等,Hooks使得函数组件也能拥有类组件的能力。
- 特点：声明式编程，只需要描述UI样式，不需要关心具体的实现细节，代码易于理解与调试。组件化，将UI拆分成独立可复用的组件，每个组件各自负责渲染和状态管理，可复用性和可维护性提高。单向数据流，数据通过props从上往下传递，状态的变化通过回调函数向上传递，使得数据流更清晰，易于追踪和调试。

2. 虚拟DOM的工作原理及其性能优化机制
虚拟DOM是React中的核心概念，它是一个轻量级的JavaScript对象，表示真实DOM的映射。当组件状态变化时，React会创建一个新的虚拟DOM树，然后通过Diff算法与旧的虚拟DOM树进行比较，找出需要更新的最小变化集，最后批量更新到真实DOM上。
性能优化机制：
Diff算法优化：采用同级比较策略，当节点类型不同时直接替换整个子树
Key值优化：为列表项提供稳定的key，帮助React准确识别元素变化
批量更新：将多个状态更新合并为单次渲染，减少DOM操作次数

3. 受控组件与非受控组件的区别
受控组件：
表单项的值由React的state控制
通过onChange事件同步状态变化
数据流是单向的，便于管理和验证
非受控组件：
表单项的值由DOM自身维护
通过ref获取DOM节点的当前值
代码更简洁，但失去了React对数据的完全控制

4. React组件通信的主要方式
父子组件通信：通过Props传递数据，Callback函数回传事件
兄弟组件通信：状态提升到共同的父组件，或使用全局状态管理
跨层级组件通信：Context API实现数据共享
复杂应用通信：Redux、Zustand、MobX等状态管理库
任意组件间通信：事件总线或发布订阅模式

5. React虚拟DOM执行流程
- 初始渲染阶段
	 - 组件首次渲染时，React创建组件树的虚拟DOM表示
虚拟DOM是一个轻量级的JavaScript对象树
每个虚拟DOM节点对应一个真实DOM节点的描述
- 状态更新触发
当组件状态（state）或属性（props）发生变化时
React会重新执行组件的render方法
生成新的虚拟DOM树
- Diff算法比较
React使用Diff算法比较新旧两棵虚拟DOM树
比较策略包括：
节点类型不同时，直接替换整个子树
节点类型相同时，比较属性变化
列表节点通过key值进行高效识别
- 差异收集
React计算出需要更新的最小变更集合
收集所有需要进行的DOM操作：
添加新节点
删除旧节点
更新已存在节点的属性
移动节点位置
- 批量更新真实DOM
React将所有的DOM更新操作批量执行
一次性将变更应用到真实DOM上
避免频繁的DOM操作，提高性能
- 完整流程示例
状态变化 → 重新渲染 → 生成新虚拟DOM 
    → Diff比较 → 计算最小变更 
    → 批量更新真实DOM

- 性能优化关键点
虚拟DOM减少了直接操作真实DOM的次数
Diff算法确保只更新必要的部分
批量更新避免布局抖动和重复渲染
Key属性帮助React准确识别列表项变化
这个执行流程使得React能够以声明式的方式高效管理UI更新，开发者无需手动操作DOM，只需关注状态管理。


## 二、核心Hooks
1. useEffect依赖项的不同情况
依赖项为空数组[]：副作用仅在组件挂载后执行一次，类似componentDidMount
不写依赖项数组：每次组件渲染后都会执行，需注意闭包陷阱
依赖项有值：当依赖项发生变化时执行副作用函数
返回清理函数：在组件卸载或下次effect执行前执行清理操作

2. useMemo和useCallback的作用与优化原理
useMemo：
缓存计算结果，避免每次渲染都进行复杂计算
只有在依赖项变化时才重新计算
适用于计算量大的值
useCallback：
缓存函数本身，避免子组件因函数引用变化而重新渲染
保持函数的稳定引用
常用于传递给子组件的回调函数

3. useState与useReducer的适用场景
useState：
适用于简单的状态管理
状态更新逻辑不复杂
单个独立的状态值
useReducer：
适用于复杂的状态逻辑
状态之间存在关联性
需要多个操作修改同一状态
状态更新逻辑需要复用

## 三、组件开发
1. React组件生命周期（函数组件模拟）
挂载阶段：useEffect(() => {}, []) 模拟componentDidMount
更新阶段：useEffect(() => {}) 模拟componentDidUpdate
卸载阶段：useEffect(() => { return cleanup }, []) 模拟componentWillUnmount
错误边界：使用static getDerivedStateFromError和componentDidCatch

2. 高阶组件与Render Props的对比
高阶组件：
接收组件作为参数，返回增强后的新组件
逻辑复用能力强，但可能产生包装地狱
适用于横切关注点的功能增强
Render Props：
通过函数prop共享组件逻辑
更灵活，但嵌套层次可能较深
适用于需要动态渲染内容的场景

3. React.memo的作用与使用场景
对函数组件进行记忆化，避免不必要的重渲染
仅对props进行浅比较，可自定义比较函数
适用于渲染成本较高的纯展示组件

## 四、性能优化
1. React性能优化常用手段
- 组件记忆化：React.memo、useMemo、useCallback
- 代码分割：React.lazy + Suspense实现懒加载
- 虚拟化长列表：react-window、react-virtualized
- 避免内联对象和函数：减少不必要的重新渲染
- 使用生产构建：移除开发环境的警告和调试代码

2. 避免不必要的重新渲染
合理使用shouldComponentUpdate或PureComponent
避免在render中创建新的对象、数组或函数
使用不可变数据更新状态
拆分大型组件，隔离变化频繁的部分

🔍 React Diff 算法与 Fiber 架构
React Diff 算法
React 的 Diff 算法通过两个假设和三个策略，将传统 O(n³) 的复杂度优化到了 O(n)。
两个假设：
类型不同的元素会生成不同的树。
通过 key 属性来标识稳定的子元素。
三个策略 & 具体优化：
Tree Diff：分层对比，忽略跨层级操作。如果节点跨层级移动，React 会直接销毁并重新创建。
Component Diff：同类组件继续 Diff，异类组件直接替换。如果是同一类型的组件，React 会继续递归 Diff。如果是不同类型的组件，则会直接替换整个组件及其子节点。
Element Diff：同一层级子节点，通过唯一 key 进行 Diff。React 会通过插入、移动、删除三种操作更新子节点。key 应稳定、唯一，避免使用数组下标。
Fiber 架构
React 16 引入的 Fiber 架构，核心解决了 React 15 及之前版本递归渲染不可中断导致的页面卡顿问题。
核心问题：在 React 15 的递归渲染中，如果组件树庞大，JavaScript 线程会长时间占用主线程，导致浏览器无法及时布局和绘制（UI渲染），页面就会卡顿。
Fiber 的解决方案：
可中断与恢复：Fiber 将渲染任务拆分成多个小工作单元。React 会在浏览器每一帧（通常16.6ms）的剩余空闲时间执行这些单元，如果时间不够，就将控制权交还给浏览器，下一帧再继续，这就是 时间切片。这避免了长时间阻塞主线程。
异步渲染：Fiber 架构为 并发模式 奠定了基础，使得 React 可以在准备新页面渲染时，当前页面依然保持响应。
工作流程拆分：Fiber 架构将协调过程分为两个阶段：

Render/Reconciliation 阶段：负责计算变更，生成新的 Fiber 树，这个阶段可中断，可执行高优先级任务。
Commit 阶段：将变更一次性提交到 DOM，这个阶段同步执行，不可中断。
⚙️ 性能优化措施
性能优化需要贯穿开发流程，这里主要从编译阶段和编译后（运行时及工程化）来看。
编译阶段优化
编译阶段优化主要指借助编译器或构建工具，在代码打包成最终产物前进行的优化。
Vue 的编译时优化：Vue 的模板语法为其编译时优化提供了很大空间。
Patch Flags：在编译阶段，Vue 会对动态节点（如绑定了动态属性、类名、样式的节点）添加标记。在运行时，通过标记可以快速定位动态节点，仅对比这些有标记的内容，跳过静态节点。
Block Tree：Vue 3 将动态节点收集到一个 Block 中。更新时，直接遍历 Block 内的动态节点进行 Diff，而不需要递归整棵树，使得渲染效率与模板大小解耦，仅与动态节点数量相关。
静态提升：将静态节点或子树提升到渲染函数之外，仅创建一次，后续渲染直接复用。
Tree Shaking：Vue 3 的模块化设计支持 Tree Shaking，打包工具可以移除未使用的代码。
React 与编译时优化：React 由于 JSX 的灵活性，编译时优化手段相对较少，更多依赖运行时优化。不过，也有一些方向和工具：
React Compiler (仍在推进)：React 团队正在开发一个能够自动优化组件的编译器，例如自动记忆化（Memo），减少不必要的重渲染。
构建工具优化：使用 Webpack、Vite 等构建工具进行 Tree Shaking、代码分割，移除未引用的代码，减少包体积。
编译后与运行时优化
这主要关注代码在浏览器中运行时的效率，以及工程层面的优化。
Vue：
响应式优化：对于大型列表，如果不需要响应式，可以使用 Object.freeze() 冻结对象。对于超大列表，使用虚拟滚动，只渲染可视区域的内容。
组件优化：使用 KeepAlive 缓存组件实例，避免重复渲染。合理使用 v-once (只渲染一次) 和 v-memo (按条件记忆)。
代码分割与懒加载：使用异步组件和路由懒加载，减少初始加载体积。
// 异步组件
const AsyncComponent = defineAsyncComponent(() => import('./Component.vue'))

React：
减少重渲染：
使用 React.memo 缓存函数组件。
使用 useCallback 和 useMemo 缓存回调函数和计算值，避免子组件因 props 变化而无效重渲染。
类组件中使用 PureComponent 或 shouldComponentUpdate 进行浅比较。
代码分割与懒加载：使用 React.lazy 和 Suspense 实现组件懒加载。
const LazyComponent = React.lazy(() => import('./LazyComponent'));

通用工程化优化：
Bundle Analyzer：分析打包产物，剔除冗余代码。
依赖优化：比如配置 Webpack 的 externals，将一些大型库（如 React, Vue）通过 CDN 引入，不打入 bundle。
压缩与缓存：代码压缩（Terser），资源 Gzip/Brotli 压缩，合理配置 HTTP 缓存。
