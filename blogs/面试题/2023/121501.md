一、 Vue 核心概念
MVC 和 MVVM 的区别
MVC 是 Model（模型）-View（视图）-Controller（控制器）的缩写。Controller 负责从 View 读取数据，控制用户输入，并向 Model 发送数据。View 和 Model 之间的通信由 Controller 操控。
MVVM 是 Model（模型）-View（视图）-ViewModel（视图模型）的缩写。ViewModel 通过数据绑定实现 Model 到 View 的转化，通过DOM 事件监听实现 View 到 Model 的转化，从而实现了数据的双向绑定，是自动化的。Vue 框架的设计受到了 MVVM 思想的启发。
Vue 组件中 data 为什么必须是函数？
在 Vue 中，组件是可复用的。如果 data 是一个对象，那么所有组件实例将共享引用同一个数据对象，修改其中一个实例的数据会影响所有其他实例，这显然不是我们想要的。而使用函数返回对象，每次创建组件实例都会调用该函数，返回一个全新的数据对象，这样每个实例都能维护自己独立的数据拷贝，避免了状态污染。
SPA 单页面应用的优缺点
优点：

用户体验好：内容改变无需重新加载整个页面，避免不必要的跳转和重复渲染。
服务器压力小：前后端职责分离，后端只需提供数据接口。
缺点：

首次加载耗时可能较多：需要一次性加载所需的 JavaScript 和 CSS 文件。
SEO 难度较大：由于所有内容都在一个页面中动态替换，对搜索引擎优化不太友好。
二、模板与指令
v-if 和 v-show 的区别
v-if 是“真正”的条件渲染，因为它会确保在切换过程中条件块内的事件监听器和子组件适当地被销毁和重建。如果初始条件为假，则什么也不做，直到条件变为真时才会开始渲染条件块。
v-show 不管初始条件是什么，元素总是会被渲染，并且只是简单地基于 CSS 的 display 属性进行切换。
使用场景：v-if 有更高的切换开销，而 v-show 有更高的初始渲染开销。因此，如果需要非常频繁地切换，则使用 v-show 较好；如果在运行时条件很少改变，则使用 v-if 较好。
v-if 与 v-for 为什么不建议一起使用？
在 Vue 2 中，v-for 的优先级比 v-if 更高，这意味着 v-if 将分别重复运行于每一个 v-for 循环中，可能造成不必要的性能负担。通常可以通过以下方式解决：
如果目的是为了过滤列表项，可以使用计算属性预先过滤出需要的数据，然后用 v-for 遍历计算属性。
如果目的是为了根据条件判断是否渲染整个列表，可以将 v-if 移动至容器元素上。
v-for 为什么要加 key
key 是 Vue 中虚拟 DOM 节点的唯一标识。它的作用主要是在新旧虚拟 DOM 对比（diff 算法）时，帮助 Vue 更准确、更快速地识别节点。
更准确：避免“就地复用”带来的状态问题。带 key 时，会根据 key 的变化来重新排列元素顺序，并移除/销毁 key 不存在的元素。
更快速：利用 key 的唯一性，可以生成一个映射图，直接通过 key 找到对应的节点，比遍历方式更快。
三、 Vue2 相关
Vue2 的生命周期
Vue2 的生命周期主要可以分为四个阶段，包含 8 个主要的钩子函数：
创建阶段（Creation）：

beforeCreate：实例刚被创建，数据观测和事件配置之前。
created：实例创建完成，数据观测和事件配置已完成，但 DOM 还未生成。
挂载阶段（Mounting）：

beforeMount：模板已编译，但尚未挂载到页面中。
mounted：实例已挂载到 DOM 上，可以操作 DOM。
更新阶段（Updating）：

beforeUpdate：数据更新时调用，虚拟 DOM 重新渲染和打补丁之前。
updated：数据更新导致虚拟 DOM 重新渲染和打补丁之后。
销毁阶段（Destruction）：

beforeDestroy：实例销毁之前，此时实例仍然完全可用。
destroyed：实例销毁后调用，所有子实例也会被销毁。
Vue2 的响应式原理
Vue2 使用 Object.defineProperty() 来劫持各个属性的 getter 和 setter。
在初始化数据时，Vue 会遍历 data 对象中的所有属性，并使用 Object.defineProperty 将其转化为 getter/setter。
当获取数据时，会触发 getter 进行依赖收集，记录哪些组件依赖了这个数据。
当修改数据时，会触发 setter，并通知所有依赖于此数据的 watcher 进行更新，从而触发视图重新渲染。
局限性：Object.defineProperty 无法检测到对象属性的新增或删除，以及数组索引和长度的变化，所以 Vue 提供了 Vue.set 和 Vue.delete 来解决这个问题。
Vue 组件间通信方式
父子组件通信：

props / $emit：父组件通过 props 向子组件传递数据，子组件通过 $emit 触发事件向父组件传递数据。
ref 与 $parent / $children：通过 ref 属性获取子组件实例，或通过 $parent / $children 访问父/子实例。
跨层级组件通信：

provide / inject：祖先组件通过 provide 提供数据，子孙组件通过 inject 注入数据。
$attrs / $listeners：包含了父作用域中不作为 prop 被识别的特性和事件监听器。
任意组件通信：

EventBus（事件总线）：创建一个空的 Vue 实例作为中央事件总线，通过 $emit 和 $on 来触发和监听事件。
Vuex：官方状态管理库，用于复杂应用的状态集中管理。
四、 Vue3 新特性
Vue3 相比 Vue2 的改进
性能提升：

使用 Proxy 重写响应式系统，性能更好，并能监听动态新增/删除的属性以及数组索引和长度的变化。
虚拟 DOM 重写，引入了编译时优化（如静态提升、Patch Flag）。
更好的 Tree-shaking 支持，打包体积更小。
Composition API：提供了基于函数的 API，允许更灵活的逻辑组织和复用，解决了 Options API 在复杂组件中逻辑关注点分散的问题。
更好的 TypeScript 支持：源码使用 TypeScript 重写，提供更好的类型推断。
新组件：引入了 `<Teleport>`（将组件内容渲染到指定 DOM 节点）、`<Suspense>`（处理异步组件加载状态） 和 Fragments（多根节点模板）等新特性。
Composition API 和 Options API 的区别
代码组织方式：

Options API 将代码按选项类型（data, methods, computed 等）组织，逻辑关注点可能分散在不同选项中。
Composition API 允许按功能逻辑组织代码，相关逻辑可以集中在一起，更利于维护和复用。
逻辑复用：

Options API 主要通过 mixins 复用逻辑，容易导致命名冲突和数据来源不清晰。
Composition API 通过组合式函数（Composables）实现逻辑复用，类似 React Hooks，更灵活清晰。
TypeScript 支持：Composition API 对 TypeScript 提供了更好的类型支持。
ref 和 reactive 的区别
数据类型：

ref 可以接收基本类型和对象类型。对于基本类型，ref 通过自身的响应式机制实现；对于对象类型，其内部会调用 reactive 进行深层响应转换。
reactive 仅用于接收对象类型（对象、数组）。
访问/修改方式：

在 JavaScript 中，访问和修改 ref 的值需要使用 .value 属性。在模板中会自动解包，无需 .value。
reactive 包装的对象可以直接访问和修改其属性，无需 .value。
使用场景：

管理简单值或需要替换整个对象引用时，使用 ref。
管理复杂的响应式对象（如表单数据、嵌套较深的对象）时，使用 reactive。

五、Vue 核心原理与机制
这些题目帮助你理解Vue的内部工作机制，是面试中的重点。
Vue 的模板编译原理是什么？
Vue 的模板编译过程是将模板（template）转换为渲染函数（render）的过程，主要包括以下步骤：
解析（Parse）：将模板字符串解析成抽象语法树（AST），识别出模板中的标签、属性、指令和文本节点。
优化（Optimize）：遍历 AST，标记静态节点和静态根节点。这些节点在后续更新渲染时可以被跳过，从而提升性能。
代码生成（Generate）：将优化后的 AST 转换为可执行的渲染函数代码字符串，这个字符串通常是一个 with 语句包装的 new Function 代码块，执行后会返回虚拟 DOM 节点。
Vue 的 NextTick 是什么，有什么作用与原理？
作用：nextTick 是一个全局 API，用于在下次 DOM 更新循环结束之后执行延迟回调。在修改数据后立即使用 nextTick，可以获取更新后的 DOM。
原理：Vue 的 DOM 更新是异步的。当数据变化时，Vue 不会立即更新视图，而是开启一个队列，并缓冲在同一事件循环中发生的所有数据变更。在内部，nextTick 会尝试使用原生的 Promise.then、MutationObserver、setImmediate，如果当前环境不支持，则会降级为 setTimeout 来调度这个回调函数，确保回调在 DOM 更新后执行。
说一下 Vue 的虚拟 DOM 是什么，以及它的 Diff 算法？
虚拟 DOM (Virtual DOM)：是一个用 JavaScript 对象来描述真实 DOM 结构和属性的方式。它是真实 DOM 的一层抽象，通过对比新旧虚拟 DOM 的差异，可以最小化地对真实 DOM 进行操作，提升性能。
Diff 算法：Vue 的 Diff 算法是同级比较的。当数据变化导致虚拟 DOM 树改变时，Vue 会对比新旧两棵虚拟 DOM 树。其核心策略是：

比较只会在同层级的节点间进行，不会跨层级比较。
首先比较两个根节点是否是相同类型的节点。
如果是相同节点，则比较两者的属性和子节点。
在比较子节点时，Vue 采用了双端比较的算法，通过四种猜测（头头、尾尾、头尾、尾头）来寻找可复用的节点，从而高效地更新子节点。
Vue.mixin 的使用场景和原理？
使用场景：Vue.mixin 用于全局注册一个混入（mixin），它会影响之后创建的每一个 Vue 实例/组件。常用于注入组件间的公共逻辑，例如一些通用的方法或生命周期钩子处理。但需谨慎使用，因为它可能造成命名冲突和来源不清晰。
原理：当组件初始化时，会调用合并策略（mergeOptions），将 mixin 对象中定义的选项（如 data、methods、生命周期钩子等）与组件自身的选项进行合并。对于对象形式的选项（如 data），会递归合并，以组件自身选项优先；对于生命周期钩子函数，会被合并成一个数组，混入对象的钩子将先于组件自身钩子调用。
六、 Vue 3 新特性与进阶用法
这部分聚焦于 Vue 3 带来的革命性变化，是区分你与只了解 Vue 2 的开发者的关键。
Vue 3 的编译优化有哪些？
Vue 3 在编译阶段进行了大量优化，显著提升了运行时性能：
静态提升 (Static Hoisting)：将模板中的静态节点或静态节点树提升到渲染函数之外。这意味着这些静态内容只在初次渲染时创建一次，后续更新时会直接复用，无需重新创建。
Patch Flag：在编译阶段，Vue 会对动态节点（即内容或属性会变化的节点）添加一个标记（Patch Flag）。在后续的虚拟 DOM Diff 过程中，Vue 可以根据这些标记快速定位动态部分，并只比对带有标记的节点，跳过静态内容，大大提升了 Diff 效率。
Tree-Shaking 支持：Vue 3 的代码结构设计得更利于 Tree-Shaking，使得在项目构建时，未被使用的 Vue API 可以被安全地移除，从而减小最终打包体积。
Vue 3 中 Ref 和 Reactive 的区别是什么？
两者都用于创建响应式数据，但有重要区别：
数据类型：ref 可以接收基本类型（如 string, number）和对象类型。对于对象类型，其内部会调用 reactive 进行转换。reactive 仅用于接收对象类型（对象、数组、Map, Set）。
访问/修改方式：在 JavaScript 中，访问和修改 ref 的值需要使用 .value 属性。在模板中，ref 会自动"解包"，无需 .value。reactive 包装的对象可以直接访问和修改其属性。
使用场景：管理简单值或需要替换整个对象引用时，使用 ref。管理复杂的响应式对象（如表单数据、嵌套较深的对象）时，使用 reactive。
Vue 3 中 Watch 和 WatchEffect 的区别是什么？
两者都用于观察响应式数据的变化并执行副作用，但用法不同：
依赖收集方式：watch 需要显式指定要监听的一个或多个数据源。watchEffect 则会自动收集其同步执行期间用到的所有响应式属性作为依赖。
回调参数：watch 的回调函数可以获取到变化前后的值。watchEffect 则无法获取变化前的值。
执行时机：watch 是惰性的，默认不会立即执行（可通过配置 immediate: true 改变）。watchEffect 会立即执行一次，用于收集依赖。
Vue 3 中 Teleport 和 Suspense 组件的作用？
Teleport：允许我们将组件的一部分模板"传送"到 DOM 中其他位置，而不影响组件的逻辑结构。常见使用场景包括模态框（Modal）、通知提示、全局弹窗等，这些元素通常需要脱离当前组件层级，避免样式或层级问题。
Suspense：用于处理异步组件的加载状态。它提供一个 #default 插槽用于放置异步组件，和一个 #fallback 插槽用于显示加载中的后备内容。当异步组件加载时，会显示 fallback 内容，加载完成后则显示异步组件。
七、 性能优化与最佳实践
了解这些优化手段，能体现你对构建高性能 Vue 应用的思考。
Vue 3 中 v-memo 指令的作用和使用方法？
v-memo 是 Vue 3.2 引入的一个新指令，用于优化渲染性能，特别是大型列表的渲染。
作用：它可以对子树的渲染结果进行缓存，只有当其依赖的特定值发生变化时，才会重新渲染该子树。
使用方法：v-memo 接收一个依赖值数组。只有当数组中的任何一个值发生变化时，对应的元素及其子元素才会更新。这对于确保大型 v-for 列表的高效更新非常有用。
```html
<ul v-memo="[products]">
  <li v-for="product in products" :key="product.id">{{ product.name }}</li>
</ul>
```
Vue 3 中如何优化项目性能？
除了上述的编译优化和 v-memo，还有以下常见优化方向：
代码分割与懒加载：使用 defineAsyncComponent 定义异步组件，并结合 Vue Router 的 import() 语法实现路由懒加载，减少初始包体积。
缓存优化：合理使用 keep-alive 组件缓存不活动的组件实例，避免重复渲染。
渲染优化：对于长列表，考虑使用虚拟列表技术，只渲染可视区域内的元素。同时，根据场景合理使用 v-show 和 v-if。
在 Vue 项目中，如何做错误捕获（错误处理）？
全局错误处理：使用 Vue.config.errorHandler 捕获组件渲染函数、侦听器或生命周期钩子中抛出的未捕获错误。
生命周期钩子：在 errorCaptured 生命周期钩子中捕获子孙组件的错误。
异步错误：对于 Promise 异步操作，使用 .catch() 进行错误捕获。
第三方监控：集成如 Sentry 等错误监控系统。
 八、路由、性能优化与工程化
Vue Router 的核心概念是什么？
   Vue Router 是 Vue.js 的官方路由管理器
路由配置：通过定义路由映射表来指定 URL 与组件之间的对应关系
路由模式：主要包括 hash 模式和 history 模式。
导航守卫：提供了一系列钩子函数（如 beforeEach, beforeResolve, afterEach）用于在路由跳转前后进行权限控制或处理
如何优化 Vue 应用的性能？
代码层面：
使用 v-show 和 v-if 智能切换
使用 computed 缓存计算结果
使用 key 提升列表渲染效率
合理使用异步组件和路由懒加载，通过 defineAsyncComponent 或 import() 实现
使用 Object.freeze() 冻结不需要响应式变化的大数据对象。
构建和部署：
利用 Vue CLI 或 Vite 进行代码压缩、分割。
开启 Gzip 压缩。
使用 CDN 加速静态资源加载。
其他：
使用 v-once 渲染只渲染一次的元素或组件
对于大型表单，可考虑使用 Object.create(null) 创建纯对象。
对于大量数据的列表，考虑使用虚拟滚动
Vue CLI / Vite 在 Vue 项目中的作用是什么？
Vue CLI：一个基于 Node.js 的命令行工具，用于快速搭建 Vue 项目骨架，提供了项目创建、开发服务器、构建打包等功能
Vite：一种新型的前端构建工具，提供更快的开发服务器启动和模块热更新，尤雨溪推荐在 Vue 3 项目中使用。
