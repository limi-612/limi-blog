1. 搭建

1.1 创建

// 重点：1.创建 createApp(根组件) 2. 挂载 .mount("根节点id")
import { createApp } from "vue";
const app = createApp({
  data() {
    return {
      count: 1,
    };
  },
});
app.mount("#app");
// 应用实例会暴露一个.config 对象允许配置应用级的选项，如全局配置、错误处理、插件、自定义指令、全局组件等。
app.config.errorHandler = (err, instance, info) => {
  // 捕获所有子组件上的错误
  // 错误处理函数
};

API：

  • createApp 应用实例
  • createSSRApp 以 SSR 激活模式创建一个应用实例，用法与 createApp 相同
  • app.mount 将应用挂载在一个容器元素中
  • app.unmount 写在一个已挂载的应用实例
  • app.onUnmount 注册一个回调函数，在应用卸载时调用
  • app.component 注册全局组件
  • app.directive 注册全局自定义指令
  • app.use 注册插件
  • app.mixin 应用一个全局 mixin，作用于应用中的每个组件实例
  • app.provide 全局注入
  • app.runwithContext 使用当前应用作为注入上下文执行回调函数
  • app.version 获取当前应用所使用的 vue 版本
  • app.config 应用实例会暴露一个 config 对象，允许配置应用级选项，如全局配置、错误处理、插件、自定义指令、全局组件等。
  • app.config.errhandler 为应用内抛出的未捕获错误指定一个全局处理函数
  • app.config.warnHandler 为 Vue 运行时警告指定一个自定义处理函数
  • app.config.performance 性能表现追踪
  • app.config.compileOptions 配置运行时编译器的选项
  • app.config.globalProperties 注册能够被应用内所有组件实例访问到的全局属性的对象
  • app.config.optionMergeStrategies 配置全局选项的合并策略
  • app.config.idPrefix 创建元素时的 id 前缀
  • app.config.throwUnhandledErrorInProduction 配置是否在生产环境抛出错误

面试题：

(1). createApp 底层原理

创建 vue 实例的 API，创建独立的应用上下文，初始化组件实例配置，设置应用范围内的共享数据和方法，返回包含 mount、use、component 等方法应用实例。

(2). mount 底层原理

接收一个 DOM 元素，查找目标元素，编译根组件模板或使用渲染函数，创建虚拟 DOM，将虚拟 DOM 渲染成真实 DOM，挂载到目标元素中。

(3). Vue2 和 Vue3 创建根实例的区别
  • Vue2：Vue 2 使用 new Vue() 方式创建根实例
  • Vue3：Vue 3 使用 createApp() 创建根实例, 提供更好的封装性和多应用实例的支持
  • 每个 createApp 创建的应用实例相互隔离，不会相互影响

1.2 API 风格

Vue 组件书写风格：1. Options API (选项式 API) 2. Composition API (组合式 API)

<template>
  <div>{{ count }}</div>
</template>
<script>
export default {
  data() {
    return {
      count: 1,
    };
  },
  methods: {
    // 组件方法
  },
  mounted() {
    // 组件创建完成
  },
};
</script>

<script setup>
import { ref } from "vue";
const count = ref(1);
const onAdd = () => {
  count.value++;
};
</script>
<template>
  <div>{{ count }}</div>
  <button @click="onAdd">+</button>
</template>

面试题

(1). Options API (选项式 API) 和 Composition API (组合式 API) 的区别
  • 代码组织方式：options API 按照功能类别组织代码，将 data、methods、mounted、computed、watch 等选项分离在不同区域中；composition API 按照逻辑功能组织代码，相关联的响应式数据、方法、计算属性等可以放在一起。
  • 逻辑复用：options API 主要通过 mixins 实现逻辑复用，但容易出现命名冲突和数据来源不清晰的问题；composition API 通过 composable 函数实现逻辑复用，更加灵活易于维护。
  • TypeScript: options API 对 typescript 支持有限，类型推导不完善；composition API 原生支持 Typescript，提供更好的类型推导和开发体验。
  • 学习曲线：options API 概念相对简单，适合初学者快速上手；composition API 需要理解响应式系统和组合逻辑的概念。
  • 适用场景：options API 适用于简单的组件和快速原型开发；composition API 更适合大型项目和复杂开发，便于逻辑组织和维护。
  • 响应式数据声明：options API 通过在 data()函数中返回对象形式声明响应式数据；composition API 通过使用 ref 和 reactive API 显式声明响应式数据。
(2). Vue2 与 Vue3 的区别?
  • 创建应用实例的区别：Vue2 使用 new Vue() 来创建根实例，无法创建多个实例；Vue3 使用 createApp() 创建应用实例，提供更好的封装性和支持多个应用实例。
  • 响应式系统：Vue2 基于 Object.defineProperty 实现响应式，存在一些限制（无法检测数组索引变化、新增删除属性等）；Vue3 基于 Proxy 实现响应式，性能更好，功能更强大，能检测到更多类型的变更。
  • Composition API：Vue2 只支持 Options API，按照选项组织代码（data 、methods、computed、watch 等）；Vue3 同时支持 Options API 和 Composition API ，可以通过 <script setup> 语法糖简化组件编写。
  • 性能优化：Vue3 进行了大量性能优化，包括更小的包体积、更快的更新速度、更好的内存使用效率；Tree-shaking Vue3 更好的支持 tree-shaking，未使用的功能不会被打包。
  • 多根节点：Vue2 组件模板必须有一个根元素；Vue3 支持多个根节点（Fragment）。
  • Teleport：Vue3 引入了 Teleport 组件，可以将子组件渲染到 DOM 树的任意位置。
  • Suspense: Vue3 提供了 Suspense 组件来处理异步依赖（如异步组件加载）。
  • 更好的 Typescript 支持：Vue3 使用 TypeScript 重写，提供了更好的类型推断和开发体验。
  • 全局 API 的改变：Vue2 许多全局 API 直接挂载在 Vue 构造函数上；Vue3 全局 API 现在是在应用实例的方法，实现了更好的封装。
