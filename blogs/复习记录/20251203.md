## 1.组合式 API

### 1.1 setup()

#### 1.1.1 基本使用

```vue
<script>
import { ref } from "vue";
export default {
  setup() {
    // async setup() 只有该组件在Suspense中才可以使用async
    const count = ref(1);
    const arr = ref([]);
    return {
      // setup() 函数返回的对象会成为组件的响应式数据
      count, // 暴露给模板
    };
  },
};
</script>
```

#### 1.1.2 访问 props

setup() 函数接收一个参数，该参数是 props 对象, 是响应式的。

```vue
<script>
import { toRefs } from "vue";
export default {
  props: {
    title: String,
  },
  setup(props) {
    console.log(props.title);
    // 可以使用toRefs进行解构，保持响应式
    const { title } = toRefs(props);
    // 也可以使用toRef进行单个属性转换成ref
    const title2 = toRef(props, "title");
    return { title, title2 };
  },
};
</script>
```

#### 1.1.3 访问 context

```vue
<script>
export default {
  setup(props, context) {
    //  setup(props, { attrs, slots, emit, expose }) 可以直接解构上下文对象，因为是非响应式的
    //   透传attribute
    console.log(context.attrs);
    // 插槽
    console.log(context.slots);

    */
  },

</script>
```

#### 1.1.4 与渲染函数一起使用

setup 也可以返回一个渲染函数

```vue
<script>
import { h, ref } from "vue";
export default {
  setup(props, { expose }) {
    const count = ref(1);
    const increment = () => ++count.value;
    // 注意：返回一个渲染函数将会阻止我们返回其他东西，可以使用expose() 解决这个问题
    expose({ increment });
    return () => h("div", {}, "hello world" + count.value);
  },
};
</script>
```

### 1.2 响应式：核心

#### 1.2.1 ref()

接收一个参数，返回一个响应式数据对象，数据对象.value 可以访问响应式数据

```vue
<script>
import { ref } from "vue";
export default {
  setup() {
    const count = ref(1);
    const onAdd = () => ++count.value;
    return {
      count,
    };
  },
};
</script>
```

面试题：

1. ref 底层原理？

- Vue 使用 getter 和 setter 来拦截对 .value 的访问和修改，从而触发依赖收集和更新通知。

2. ref 怎么触发依赖收集和更新通知？

- 依赖收集：当代码读取 ref.value 时，触发 RefImpl 的 getter，在 getter 中调用 track 函数进行依赖收集，将当前正在执行的副作用函数（如组件渲染、watch 等）作为依赖存储起来。
- 更新通知：当修改 ref.value 时，触发 setter，更新\_value 属性，调用 trigger 触发依赖更新通知，通知所有收集到的依赖（副作用函数）重新执行。

3. ref 和 reactive 的区别？

- **数据类型支持**：ref 支持所有数据类型，对基本类型进行包装，对引用类型会自动调用 reactive 进行处理；reactive 只支持对象和数组等引用类型。
- **访问方式**：ref 需要通过.value 访问，在模板中使用时会自动解包；reactive 直接访问属性，无需.value。
- **底层原理**：ref 基于 javaScript 的 getter/setter 实现，对基本类型值进行包装，创建一个包含.value 属性的对象；reactive 基于 Proxy 实现，创建目标对象的代理，拦截各种操作行为。

4. ref 为什么返回一个对象？

- 保持响应式特性：将基本类型值包装在一个对象中，可以通过对该对象的.value 属性访问和修改来实现响应式追踪。
- 统一访问接口：返回对象并通过.value 访问，提供了统一的 API 接口，无论是基本类型还是对象类型都可以一致处理。
- 兼容性和便利性：对于对象类型，ref 内部会自动调用 reactive 进行处理，不需要区分基本类型和引用类星星，都可以使用相同的 ref API。

5. ref 在模板渲染过程中自动解包的底层原理？

- 当在模板表达式中访问 ref 变量时，vue 会通过 isRef() 检查该变量是否为 ref 对象，如果是 ref 对象，则自动返回其.value 值。
- 提升开发体验，避免在模板中频繁书写.value，保持一致性，在模板中可以直接像使用突通变量一样使用 ref，减少开发者忘记添加.value 的错误。

#### 1.2.2 computed()

接受一个 getter 函数，返回一个只读的响应式 ref 对象，数据对象.value 可以访问响应式数据。也可以接收一个对象，对象中包含 getter 和 setter 函数，来创建一个可写的 ref 对象。

```vue
<script>
export default {
  setup() {
    const count = ref(1);
    const doubleCount = computed(() => count.value * 2, {
      /**
       * 调试 onTrack,onTrigger
       * onTrack 监听数据变化
       * onTrigger 监听数据触发
       */
      onTrack(e) {
        debugger;
      },
      onTrigger(e) {
        debugger;
      },
    });

    const count2 = ref(1);
    const doubleCount2 = computed({
      get: () => count2.value * 2, // 20
      set: (val) => (count2.value = val), // 10
    });
    dboubleCount2.value = 10;
    console.log(doubleCount2.value); // 20
  },
};
</script>
```

#### 1.2.3 reactive()

返回一个对象的响应式代理

- ref 解包

```vue
<script>
import {reactive， ref} from 'vue'
export default {
  setup() {
    const count = ref(1);
    const obj = reactive({count});
    // 这个时候 ref 就会被解包（意思是obj.count 不需要.value）
    console.log(obj.count === count.value) // 1 === 1 true

    count.value++;
    console.log(obj.count === count.value) // 2 === 2 true

    obj.count++;
    console.log(count.value === count.value) // 3 === 3 true
  }
}
</script>
```

- 当访问某个响应式数组或 Map 的原生合集类型中的 ref 元素时，不会执行 ref 的解包

```vue
<script>
import {reactive， ref} from 'vue'
export default {
   setup(){
    const arr = reactive([ref(1)])
    // 需要.value
    console.log(arr[0].value) // 1

    const map = reactive(new Map([["key", ref(1)]]))
    // 需要.value
    console.log(map.get("key").value)) // 1
   }

}
</script>
```

面试题：

1. reactive 底层原理

- **基于 proxy 实现**：reactive 利用 javascript 的 proxy API 创建目标对象的代理，从而拦截对象的各种操作。
- **依赖收集和派发更新**：在 getter 中进行依赖收集（track），当访问代理对象的属性时，会将当前的副作用（如组件渲染、watch 等）作为依赖收集起来。在 setter 中进行更新派发（trigger），当修改代理对象的属性时，会触发之前收集到的依赖，执行相应的副作用函数。

2. Reflect 做了什么？

- **Reflect API**：Reflect 是一个内置对象，提供了一些方法，用于操作对象。这些方法与 Object 的方法类似，但更安全，不会抛出错误。Reflect 方法可以确保正确的 this 绑定和行为。
- **Reflect.get()**：Reflect.get() 方法用于读取对象的属性值。
- **Reflect.set()**：Reflect.set() 方法用于设置对象的属性值。

3. 为什么 vue3 不用 Object.defineProperty 了？

- **无法监听新增/删除属性**：Object.defineProperty 在创建会一次性递归遍历对象的所有属性，这个过程只在初始化阶段发生一次，导致新增/删除属性无法监听。对于新增或删除属性，需要通过 Vue.set()或 Vue.delete() 来实现；Proxy 可以拦截对象的所有操作，包括属性的新增和删除。
- **无法监听数组索引变化**：Object.defineProperty 无法有效监听通过索引设置数组项的操作，需要通过重写数组方法（push、pop 等）来实现响应式；Proxy 可以完美监听数组的所有变化。
- **性能更好**：Object.defineProperty 需要在创建响应式对象时遍历所有属性并逐一定义 getter、setter；Proxy 在处死话时不需要递归遍历所有属性，只在访问属性时才进行拦截处理。
- **功能更强大**：Proxy 可以实现更丰富的功能，如拦截属性的读取、设置、删除、枚举、属性验证等，而 Object.defineProperty 只能实现属性的读取和设置。
- **代码更简洁**：使用 Proxy 的实现更加直观和简洁，不需要像 Vue2 那样维护复杂的边界情况处理逻辑。

#### 1.2.4 readonly()

接受一个对象或是一个 ref，返回一个原值的只读代理

```vue
<script>
import {reactive， readonly} from 'vue'
export default {
  setup() {
    const obj = reactive({count: 1});
    const readonlyObj = readonly(obj);
    obj.count++; // 2
    readonlyObj.count++; // 会得到一个警告
  }
}
</script>
```

面试题：

1. readonly 底层原理

- **基于 proxy 实现**：readonly 与 reactive 类似。都是基于 javascript 的 proxy API 实现，创建一个目标对象的代理，但会对所有修改操作进行拦截并阻止。
- **拦截修改操作**：当尝试修改只读对象时，Vue 会在 Proxy 的 set、deleteProperty 等陷阱（trap）中阻止这些操作。
- **保持响应式特性**：虽然对象是只读，但仍然保持响应式特性，意味着当原始对象发生变化时，依赖于只读代理的副作用（如组件渲染）仍会被正确触发
- **嵌套对象处理**：readonly 会递归地将整个对象树转换为只读，包括所有嵌套的对象属性。
- **开发环境警告**：在开发环境中，Vue 会在修改只读对象时发出警告，提示开发者不要修改只读对象。

#### 1.2.5 watchEffect()

立即运行一个函数，同时响应式追踪其依赖，并在依赖更改时重新执行。

- 第一个参数就是要运行的副作用函数。副作用函数的参数也是一个函数，用来注册清理回调。清理回调会在该副作用下次执行之前被调用，可以用来清理无效的副作用，例如等待中的异步请求。
- 第二个参数是一个可选的选项，可以用来调整副作用的刷新时机或调试副作用的依赖。

1. 基础使用

```vue
<script>
import { ref, watchEffect } from "vue";
export default {
  setup() {
    const count = ref(1);
    watchEffect(() => {
      console.log(count.value);
    });
    // 输出 1， 默认刷新时机是立即执行
    count.valure++;
    // 输出 2 监听到 count.value 的变化
  },
};
</script>
```

2. 暂停、恢复、停止监听

```vue
<script>
import { ref, watchEffect } from "vue";
export default {
  setup() {
    const count = ref(1);
    const { stop, pause, resume } = watchEffect(() => {
      console.log(count.value);
    });
    // 暂停监听
    pause();
    // 恢复监听
    resume();
    // 停止监听
    stop();
  },
};
</script>
```

3. 副作用清理

```vue
<script>
import { ref, watchEffect, onWatcherCleanup } from "vue";
export default {
  setup() {
    // 1.使用第一个函数参数来注册清理回调
    watchEffect(async (onCleanup) => {
      const { response, cancel } = doAyncRequest(newId);
      // 如果id 变化，则调用cancel
      // 如果之前的请求未完成，则取消请求
      onCleanup(cancel);
      data.value = await response;
    });

    // 2.使用 onWatcherCleanup() 来注册清理回调
    watchEffect(()=>{
      const { response, cancel } = doAyncRequest(newId);
      onWatcherCleanup(cancel);
      data.value = await response;
    })
  },
};
</script>
```

#### 1.2.6 watchPostEffect()

和设置 `flush: 'post'` 相同，将会使监听器延迟到组件渲染之后再执行

#### 1.2.7 watchSyncEffect()

和设置 `flush: 'sync'` 相同，将会使监听器同步执行，在响应式依赖发生改变时立即触发侦听器

#### 1.2.8 watch()

侦听一个或多个响应式数据源，并在数据源变化时调用所给的回调函数

```vue
<script>
import { ref, watchEffect, onWatcherCleanup } from "vue";
export default {
  setup() {
    const fooRef = ref(1);
    const barRef = ref(2);
    // [foo, bar], [prevFoo, prevBar]: 当侦听多个来源时，回调函数接受两个数组，分别对应来源数组中的新值和旧值
    // onCleanup, 使用第一个函数参数来注册清理回调
    watch([fooRef, barRef], async ([foo, bar], [prevFoo, prevBar], onCleanup) => {
      const { response, cancel } = doAyncRequest(newId);
      // 如果id 变化，则调用cancel
      // 如果之前的请求未完成，则取消请求
      onCleanup(cancel);
      data.value = await response;
    });  //当直接侦听一个响应式对象时，侦听器会自动启用深层模式

    // 使用 onWatcherCleanup() 来注册清理回调
    watch([fooRef, barRef], ([foo, bar], [prevFoo, prevBar])=>{
      const { response, cancel } = doAyncRequest(newId);
      onWatcherCleanup(cancel);
      data.value = await response;
    })
  },
};
</script>
```

面试题：

1. watch() 底层原理？

- **依赖收集**：在首次执行时，访问 source 中的响应式数据，通过 ReactiveEffect 收集所有被访问的响应式属性作为依赖
- **变化检测**：当依赖的响应式数据变化时，触发 scheduler 调度执行回调，根据配置选项（如 flush）决定执行时机
- **回调执行**：比较新旧值确定是否需要执行回调，支持 immediate 选项控制是否立即执行

2. watchEffect() 和 watch() 的区别？

- **监听方式**：watchEffect 自动追踪回调函数内的响应式依赖；watch 显式指定要监听的响应式数据源
- **初始执行**：watch 立即执行一次，然后追踪依赖；watch 默认不立即执行，除非设置 immediate:true
- **回调函数参数**：watchEffect 回调函数不接收参数；watch 回调函数接收（newVal，oldVal）参数

### 1.4 响应式：进阶

ref()的浅层作用形式

#### 1.4.3 customRef()

创建一个自定义的 ref，显式声明对其依赖追踪和更新触发的控制方式。（自定义响应式）

```js
import { customRef } from "vue";
export function useDebouncedRef(value, delay = 200) {
  let timeout;
  return customRef((track, trigger) => {
    return {
      get() {
        track();
        return value;
      },
      set(newValue) {
        clearTimeout(timeout);
        timeout = setTimeout(() => {
          value = newValue;
          trigger();
        }, delay);
      },
    };
  });
}
```

#### 1.4.4 shallowReactive()

reactive() 的浅层作用形式

```vue
<script>
import { shallowReactive } from "vue";
const state = shallowReactive({
  foo: 1,
  nested: {
    bar: 2,
  },
});
// state.foo 是响应式的
state.foo++;
// 下层嵌套对象不会被转为响应式
isReactive(state.nested);
// state.nested.bar 不是响应式的
state.nested.bar++;
</script>
```

面试题：

1. shallowReactive() 和 reactive() 的区别？

- **响应式层级不同**：reactive() 会对整个对象进行深层次的响应式转换，包括所有嵌套的对象属性；shallowReactive() 只会对对象的第一层属性进行响应式处理，而嵌套对象则不会被转换为响应式。
- **性能差异**：reactive()由于需要递归处理所有嵌套属性，开销大；shallowReactive() 只处理第一层，性能更好，适用于不需要深层响应式的场景

2. shallowReactive() 的底层原理？

- **基于 Proxy 实现**：与 reactive() 类似，shallowReactive() 同样基于 javascript 的 Proxy API 实现，创建目标与对象的代理
- **浅层处理机制**：与 reactive() 的主要区别在于 shallowReactive() 在处理属性访问时，不会对嵌套对象自动调用 reactive() 进行深层转换
- **拦截操作范围受限**：只对顶层属性的访问（get）和修改（set）进行拦截和响应式处理，对于嵌套对象的属性操作不会触发响应式行为
- **性能优化策略**：通过限制响应式转换的深度，避免不必要的递归处理，提高初始化性能和减少内存占用

#### 1.4.6 toRaw()

根据一个 Vue 创建的代理返回其原始对象。当你使用 toRaw() 获取原始对象后，将得到一个普通的 JavaScript 对象，不再是 vue 响应式系统的代理对象。因此，对这个原始对象的修改不会触发依赖更新，不会影响界面的重新渲染，不会触发相关的 watcher 或 computed 属性更新。

```vue
<script>
import { reactive, toRaw } from "vue";
export default {
  setup() {
    const state = reactive({
      count: 0,
    });
    const rowState = toRaw(state);
    rowState.count++; // 不会触发响应式更新
    consle.log(state.count); // 1 实际上已经是 1， 但是没有触发响应

    state.count++; // 2 触发响应 界面重新渲染
  },
};
</script>
```

#### 1.4.7 markRaw()

#### 1.4.8 effectScope()

创建一个 effect 作用域，可以捕获其中所创建的响应式副作用（即计算属性和侦听器），这样捕获到的副作用可以一起处理.

```vue
<script>
import { effectScope } from "vue";
export default {
  setup() {
    const count = ref(1);
    const scope = effectScope();
    scope.run(() => {
      const doubled = computed(() => count.value * 2);
      watch(doubled, () => {
        console.log(doubled.value);
      }); // 2 传入监听器
      watchEffect(() => {
        console.log(doubled.value);
      }); // 2  无需传入监听器，自动获取监听器
    });

    scope.stop(); //处理掉当前作用域内的所有 effect
  },
};
</script>
```

### 1.5 生命周期钩子

#### setup()

setup() 函数返回一个对象，对象中的属性会成为组件的属性

#### onBeforeMount()

注册一个回调函数，在组件被挂载之前被调用。（vue2 的 beforeCreate）
组件已经完成了其响应式状态设置，但没有创建 DOM 节点。即将首次执行 DOM 渲染。

#### onMounted()

注册一个回调函数，在组件挂载完成后执行。（vue2 的 created）
所有同步组件都已经被挂载，自身 DOM 树已经创建完成并插入了父容器中。这里可以执行需要访问组件所渲染的 DOM 相关的副作用。

#### onBeforeUpdate()

注册一个钩子，在组件即将因为响应式状态变更而更新其 DOM 树之前调用。

#### onUpdated()

注册一个回调函数，在组件因为响应式状态变更而更新其 DOM 树之后调用。

#### onBeforeUnmount()

注册一个钩子，在组件即将被卸载之前调用。

#### onUnmounted()

注册一个钩子，在组件挂载后调用。

#### onErrorCaptured()

注册一个钩子，在捕获了后代组件传递的错误时调用。

#### onRenderTracked()

注册一个调试钩子，当组件渲染过程中追踪到响应式依赖时调用。

#### onRenderTriggered()

注册一个调试钩子，当响应式依赖的变更触发了组件渲染时调用。

#### onActivated()

注册一个回调函数，若组件实例 `<KeepAlive>` 缓存树的一部分，当组件被插入到 DOM 中时调用。

#### onDeactivated()

注册一个回调函数，若组件实例是 `<KeepAlive> `缓存树的一部分，当组件从 DOM 中被移除时调用。

#### onServerPrefetch()

注册一个异步函数，在组件实例在服务器上被渲染之前调用

### 1.6 依赖注入

#### provide()

提供一个值，可以被后代组件注入

```vue
<script>
import { provide, ref } from "vue";
import { countSymbol } from "./injectionSymbols";
export default {
  setup() {
    // 提供静态值
    provide("name", "zhangsan");

    // 提供动态值
    const count = ref(2);
    provide("count", count);

    // 提供是将 Symbol作为key
    provide(countSymbol, count);
  },
};
</script>
```

#### inject

注入一个由祖先组件或整个应用（通过 app.provide() ）提供的值

```vue
<script>
import { inject, ref } from "vue";
import { countSymbol } from "./injectionSymbols";
export default {
  setup() {
    // 注入
    inject("name");
    inject("count");
    inject(countSymbol);
  },
};
</script>
```

#### hashInjectionContext()

如果 inject() 可以在在错误的地方 （例如 setup()）之外被调用而不触发警告，则返回 true。此方法适用于希望在内部使用 inject()而不向用户发出警告的库。

#### v-show

```html
<div v-show="isShow"></div>
```

#### v-if

基于表达式值的真假性，来条件性的渲染元素或者模板片段。

```html
<div v-if="isShow"></div>
```

#### v-else

表示 v-if 或 v-else-if 链式调用 else 块。 配合 v-if 使用，当 v-if 的条件为假时，v-else 会渲染该元素。

```html

```

#### v-else-if

表示 v-if 的 else if 块。限定：上一个兄弟必须有 v-if 或 v-else-if。

```html

```

#### v-for

基于原始数据多次渲染元素或模板块。（必须在元素上提供 key 属性）

```html
<div v-for="item in items" :key="item">{{ item }}</div>
```

面试题：

1. v-for 循环的 key 是什么作用？

- 帮助识别元素变化：Vue 使用 key 来建立虚拟 DOM 节点与真实 DOM 元素之间的映射关系。当数据更新时，Vue 可以通过比较新旧 key 快速判断出应该执行怎样的 DOM 操作。
- 优化渲染性能：Vue 可以最小化 DOM 操作次数，只更新真正发生变化的部分，避免不必要重新渲染整个列表。
- 维持组件状态和触发过渡效果：使用 key 可以保证组件的状态（如输入框内容、复选框中状态等）在列表更新时不丢失。
- 避免就地更新策略带来的问题： 如果没有提供 key，Vue 会采用 “就地更新”策略，可能导致一些意外的行为，比如表单元素的状态错乱。

2. v-for 循环的 key 的底层原理？

- 无 key 的更新机制：当未指定 key 时，vue 采用就地复用策略，依据索引顺序进行新旧虚拟节点比对。数据变动会导致大量不必要的 DOM 原地更新和潜在的组件状态错乱。
- 有 key 的更新机制：当指定了 key 时，vue 会启动 keyed Diff 算法，基于 key 进行新旧虚拟节点比对，并使用 key 进行映射，从而避免了就地更新策略带来的问题。
  - 头部/尾部同步：快速跳过相同前缀和后缀
  - 映射查找：构建旧节点 key 到索引的映射表，遍历新节点用 key 精准查找匹配。
  - 精准操作： 找到匹配，复用现有 DOM 节点，仅必要时移动位置。未找到，新建节点。旧节点未使用，卸载节点。

#### v-on

给元素绑定事件监听 （缩写 @）

###### **修饰符**

- .stop 调用 `event.stopPropagation()` 阻止事件冒泡
- .prevent 调用 `event.preventDefault()` 阻止默认行为
- .capture 添加事件监听器时使用事件捕获模式
- .self 只有事件从元素本身出发才触发处理函数
- .{keyAlias} 只在某些按键下触发处理函数
- .once 最多触发一次处理函数
- .left 只在鼠标左键事件触发处理函数
- .right 只在鼠标右键事件触发处理函数
- .middle 只在鼠标中键事件触发处理函数
- .passive 通过{passive: true} 附加一个 DOM 事件

```html
<div v-on:click="handleClick">Click me</div>
<!-- 等价于 -->
<div @click="handleClick">Click me</div>

<!-- 更多示例 -->
<!-- event 绑定 动态事件 -->
<div v-on:[event]="doThis"></div>

<!-- 内联声明 -->
<div v-on:click="doThis("hello", $event)"></div>

<!-- 缩写 动态事件 -->
<div @[event]="doThis"></div>

<!-- 停止传播 -->
<div @click.stop="doThis"></div>

<!-- 阻止默认行为 -->
<div @click.prevent></div>

<!-- 不带表达式的阻止默认事件 -->
<div @submit.prevent></div>

<!-- 链式调用修饰符 -->
<div @click.stop.prevent="doThis"></div>

<!-- 按键用于 keyAlias 修饰符 -->
<div @keyup.enter="onEnter"></div>

<!-- 点击事件将最多触发一次 -->
<div @click.once="doThis"></div>

<!-- 对象语法 -->
<div v-on="{mousedown: doThis, mouseup: doThat}"></div>

<!-- 自定义事件 -->
<MyComponent @my-event="doThis"></MyComponent>

```

#### v-bind

动态绑定一个或多个 attribute，也可以是组件的 props。

##### 缩写

`:` 或者 `.` （当 prop 修饰符）

##### 修饰符

- .camel 将短横线命名的 attribute 转变为驼峰式命名
- .prop 强制绑定为 DOM property
- .attr 强制绑定为 DOM attribute

```html
<!-- 绑定 attribute -->
<img v-bind:src="imageSrc" />

<!-- 动态 attribute 名 -->
<img v-bind:[attrName]="imageSrc" />

<!-- 缩写 -->
<img :src="imageSrc" />

<!-- 绑定对象形式 attribute -->
<div v-bind="{ id: 'container', class: 'wrapper' }"></div>

<!-- 自定义组件 props -->
<MyComponent v-bind="value" />
```

#### v-model

在表单输入元素或组件上创建双向绑定。

##### 仅限

`<input>`、`<textarea>`、`<select>`、`component`

##### 修饰符

- .lazy 监听 change 事件而不是 input 事件
- .number 将输入的合法字符串转换为数字
- .trim 移除输入内容的两端空格

```html
<input v-model="message" />
```

面试题：

1. v-model 的原理？

- v-model 是一个语法糖，本质是 v-bind 和 v-on 的组合。
- **数据绑定**：通过 v-bind 将组件数据绑定到表单元素的 value 属性。
- **事件监听**：通过 v-on 监听表单元素的输入事件。
- **数据更新** 当用户输入时，触发事件处理器更新组件数据。
- **视图更新**：数据更新后，vue 的响应式系统会自动更新视图。

#### v-slot

用于声明具名插槽或是期望接受 props 的作用域插槽。

##### 缩写

`#`

#### v-pre

跳过该元素及其所有子元素的编译。元素内具有 v-pre，所有 vue 模板语法都会被保留并按原样渲染。

#### v-once

仅渲染元素组件一次，并跳过之后的更新。

```html

```

#### v-memo

缓存一个模板的子树。为了实现缓存，该指令需要传入一个固定长度的依赖值数组进行比较。如果数组里的每一个值都与最后一次的渲染相同，那么整个子树的更新将被跳过。

```html
<!-- 缓存一个模板的子树 -->
<div v-memo="[dep1, dep2]">...</div>

<!-- 与v-for 一起使用 -->
<div v-for="item in items" v-memo="[item.id === selected]">...</div>
<!-- 当组件selected 状态改变，默认会创造大量 vnode。v-memo 用在这里本质上是在说“只有当该项的被选中状态改变时才需要更新”。 使得每一个选中窗台没有变的项你能够完全重用之前的vnode并跳过差异比较。 -->
```

面试题：

1. v-memo 的底层原理？

- **缓存存储**：为带有 v-memo 的节点维护一个特殊的缓存槽。缓存内容：上一次渲染生成的完整虚拟 DOM 子树，以及对应的依赖值快照。
- **依赖比较**：每次组件重渲染时，将 v-memo="[deps]" 中的依赖值与缓存快照进行浅层严格相等比较（使用 Object.is 或类似机制）。比较算法：按顺序逐个对比数组中的每个依赖项。
- **决策分支**：所有依赖值完全相同：直接返回缓存的虚拟 DOM 子树。任一依赖值变化：正常执行完整渲染流程，用新结果更新缓存。

#### 2.2.1 `<Transition>`

为单个元素或组件提供动画效果。

##### 属性

- name: 定义过渡效果的名称
- css：默认的过渡效果名称
- type：定义过渡效果的类型
- duration：定义过渡效果的持续时间
- mode：控制利尻/进入过渡的时序
- appear：是否对初始渲染使用过渡
- enterFromClass：用于自定以过渡 class
- enterActiveClass：用于自定义过渡 class
- enterToClass：用于自定义过渡 class
- appearFromClass：用于自定义过渡 class
- appearActiveClass：用于自定义过渡 class
- appearToClass：用于自定义过渡 class
- leaveFromClass：用于自定义过渡 class
- leaveActiveClass：用于自定义过渡 class
- leaveToClass：用于自定义过渡 class

##### 事件

- @before-enter: 元素进入过渡之前调用
- @before-leave：元素离开过渡之前调用
- @enter: 元素进入过渡时调用
- @leave: 元素离开过渡时调用
- @after-enter: 元素进入过渡之后调用
- @after-leave: 元素离开过渡之后调用
- @after-appear: 元素显示过渡之后调用
- @enter-cancelled：元素进入过渡取消时调用
